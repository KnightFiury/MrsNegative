## Review

No SQL injection is present. All three inputs are handled safely: `req.query.sort` is gated through the `SORTABLE` allowlist before interpolation; `req.query.dir` is coerced to exactly `'DESC'` or `'ASC'` in a ternary; and `req.query.q` is passed as a bound parameter (`$1`). The dynamic `ORDER BY ${sort} ${dir}` only ever contains allowlisted identifiers and a controlled direction literal, so the surface-level injection worry does not materialize.

The only genuine (minor) issue is LIKE-wildcard semantics, not injection: `term` is concatenated into an `ILIKE` pattern without escaping, so `?q=%` matches every row and `_` matches any single character. That is a behavior quirk, not a security flaw, since the input stays parameterized. Optional, even more minor: no `LIMIT`, and a leading `%` wildcard defeats any index on `name`.

The change does what the user asked (filters and sorts the admin list) and does it with an injection-safe pattern. No blocking or worth-fixing finding applies here.
