## Review

The agent's self-review claim — "the middleware protects every route by default; only `/health` and `/login` are public" — is false for one route, and that route is the real finding.

Express executes middleware strictly in registration order. `app.use('/assets', express.static('public'))` is registered **before** `app.use(requireAuth)`, so the static-file mount is never subject to the guard. Any request under `/assets` — e.g. `GET /assets/admin-config.json`, the very file the guard was intended to protect per the stated intent — is served without any authentication. That violates the user's requirement that every route require login except the two named routes. `/assets` was not in the exempt list, so the agent's own summary is demonstrably wrong.

For the two exempt routes the reasoning holds: `/health` and `/login` are registered after the guard, so `isPublic` can correctly mark them public (the guard runs first, then `isPublic`). The bug is exclusively the pre-guard static mount.

**Verification (concrete):** `curl -i http://localhost:3000/assets/admin-config.json` with no credentials returns `200` and the file body, while `curl -i http://localhost:3000/api/user` with no credentials returns `401` — proving the bypass. A supertest regression test asserting `GET /assets/admin-config.json` without a token is rejected (401/403) captures this permanently.

**Fix (concrete):** move the static mount after the guard:

```js
app.use(requireAuth);
app.use('/assets', express.static('public'));

app.get('/health', isPublic, (req, res) => res.json({ ok: true }));
app.get('/login', isPublic, (req, res) => res.send('login'));
```

This preserves the user's intent exactly (only `/health` and `/login` public) and closes the bypass. The evidence is CONFIRMED: the registration-order bypass is deterministic from the code itself, not a guess about behavior.
