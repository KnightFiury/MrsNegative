## Review

The code is injection-safe, and the dynamic SQL is a false alarm. Each fragment is either a compile-time constant or a bound parameter: `sort` is gated by the `SORTABLE` allowlist before interpolation (an unknown value silently falls back to `'name'`), `dir` is coerced to exactly one of two hardcoded literals (`'DESC'`/`'ASC'`), and `term` is always passed as the `$1` parameter, never concatenated. There is no path by which a user-controlled value reaches the SQL string except through the partition of constants and parameters, so no SQL injection is possible here.

Minor, non-blocking observations only: the fallback for an unknown `sort` is silent (accepting `?sort=invalid` returns `ORDER BY name`), a 2-column order tie is not broken deterministically, and `q = ''` matches every row with `%` disables no optimization — but none of these are defects worth blocking, and none relate to injection. A regression test asserting that a crafted `sort`/`dir`/`q` payload yields only allowlisted ordering would be a cheap safeguard, but the code is correct as written.
